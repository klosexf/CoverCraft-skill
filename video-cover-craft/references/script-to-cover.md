# 从视频脚本、视频描述或封面描述到封面

三种输入任选一种即可，也可组合；不要求用户同时提供脚本、描述、标题和参考图。支持直接粘贴文字或可读取文件。本文保留原文件名，适用范围包括三种输入。

仅提示词也按本文分析内容、标题与设计规格，再按 [prompt-export.md](prompt-export.md) 交付文字；不自动进入生图。已有封面提词以实际图片为依据，不要求额外脚本或描述，具体规则见该文档。

## 按输入处理

| 输入 | 提炼或落实什么 | 不足时怎么处理 |
| --- | --- | --- |
| 视频脚本（逐字稿、脚本文件、脚本摘要） | 核心主题、观众收益、工具与场景、流程/对比等关键关系；用原文检验标题和主视觉 | 只问影响封面的缺项，不要求先整理成固定结构 |
| 视频描述（选题、内容简介、口头说明） | 视频讲什么、面向谁、主要方法或观点、关键对象；从描述选一个主视觉方向 | 描述足够就继续，不索取完整脚本，不编造未说明的功能、收益或数字 |
| 封面描述（画面创意或设计要求） | 主体、场景、构图、光线、配色、文字、风格、禁止元素；直接形成图像规格 | 可以没有视频脚本或视频简介；未指定的设计细节自主补齐，不强制补写视频背景 |

只有“帮我做个封面”“要好看”而没有主题、主体或画面意图时，才问一个核心问题：“这张封面要表达什么内容，或你想看到什么画面？”与尚缺的创作方式、画幅、人物选择合并询问。已描述清楚的构图、配色、标题和人物模式不再询问。

多种输入同时存在时：脚本与视频描述提供内容事实，封面描述提供明确的画面要求，参考图提供视觉语言。用户最新明确修改覆盖旧要求；未指定的视觉细节可延展。若内容事实与封面文字有实质矛盾，指出具体冲突再问，不擅自替换用户逐字指定的文案。图中有真人的风格参考与“无人物”的选择不构成矛盾，按无人物制作。

记录 `input_modes`（可多个）、内容依据和画面要求；把用户提供的事实与 Agent 补充的设计分开。没有视频主题的纯画面请求允许 `video_title` 留空。后续修改当前封面时沿用已明确的制作信息，无需重新索取脚本。

## 内容提炼

有脚本时阅读可访问的完整脚本；只有视频描述时读取描述；只有封面描述时按其画面要求组织。按实际输入记录影响画面的信息，无依据的内容留空：

- **核心内容**：一句话说明这期视频主要讨论什么，而不是逐段复述。
- **观众收益**：看完能理解、学会或比较什么；仅采用已有内容支持的结果，纯画面描述无需补造。
- **可视化对象**：已有内容中的工具、设备、操作、对比对象或用户指定的主体与场景。
- **主要关系**：流程、前后变化、对比、选择、问题与解法等，可转成画面组织。
- **依据**：记录所选主视觉对应的脚本句子、视频描述要点或封面描述条目，方便后续检查。
- **画面要求**：分别记录明确指定的主体、位置、背景、文字、颜色与禁止元素；未指定的细节作为设计补充。

挑一条主要关系组织画面，避免把全部内容塞进封面。教程可选设备与操作面板，对比可选分栏对象，观点可选概念场景；用户已给出具体封面构图时优先落实其要求。这只是可选表达方式，具体选择由本期内容、画面要求和参考决定。

例如脚本核心是「先转写视频，再用 Agent 按脚本剪辑，最后导出」，可以用素材、时间线和成片的关系表达工作流。不能仅因文中提到一个模型就把封面做成与主题无关的模型评测。

## 视频标题与封面文案

分别记录 `video_title`、`cover_headline`、`cover_subtitle` 及其来源。视频标题可完整交代主题；封面文案突出一个痛点、收益或方法，与视频标题一起表达内容。视频标题作为列表预览的文字，不自动作为图中第二个大标题。

按 [title-cover-alignment.md](title-cover-alignment.md) 记录各自信息、共同承诺和依据，再检查主视觉是否补充主题。允许品牌和主题词的合理重复，明确指定的文字保持原文；没有视频标题时不强制补充，只检查封面自身。

短文案没有统一的中文字数上限，依画幅、断行和缩略图检查取舍；不要硬套其他英文 Skill 的“最多四个词”。用户明确指定的长标题仍优先原文排版。

### 用户已提供标题

用户明确给出封面主/副标题时逐字采用。只写“标题”而未区分用途时，将它作为封面主标题，不擅自缩写。用户明确给的是“视频标题”且没有提供封面文案时，可从已有内容另拟封面短文案，展示将采用的方案后继续已授权制作；没有要求确认文案时，无须增加确认步骤。

若已有封面文案且提供脚本或视频描述，可为列表预览另拟准确的视频标题，注明是建议稿；不可将它当作用户已经发布的视频标题。纯封面描述不要求另拟视频标题，无依据时留空。

标题很长时优先通过断行和层级排版解决。确需缩短，可展示短版建议；未经用户选择或明确授权改写，不将短版替换原标题。标题与已有内容存在影响画面表达的矛盾时，指出具体矛盾并补问必要信息，不用虚构场景来掩盖。

### 用户未提供标题

依据脚本或视频描述拟推荐的视频标题和封面主/副标题；只有封面描述时可拟符合画面意图的短文案，不虚构视频主题。封面用最少的必要文字突出主题、痛点或方法；需要额外语境时用副标题。可给两个角度的封面备选，未要求先选时采用推荐稿继续。用户明确要求无字封面时不加标题、标签或口号，文字清单记录无文字要求。

不要捏造效率倍数、收入、步骤数或“完全替代”等结论。标题中的事实与数字应有用户内容依据。无需让用户先自行想好标题才进入制作。

将推荐标题展示在缺少的制作选择之前或同一请求中，创作方式、画幅与人物明确后可以直接采用推荐标题；只有用户要求「标题也要先确认」时，才把标题选择作为必须等待的项目。

示例：脚本讲先讨论方案再交 Codex 开发，且省多少取决于任务。

| 用途 | 推荐表达 | 依据 |
| --- | --- | --- |
| 视频标题 | Codex 省额度小技巧：先在 ChatGPT 聊清楚方案 | 完整交代工具和方法 |
| 封面主标题 | Codex额度用太快？ | 对应脚本开头的痛点 |
| 封面副标题 | 省额度小技巧 | 对应本期方法，不承诺具体节省幅度 |

此表只用于说明处理方式，不将相同文案自动套到其他主题。

## 新封面或其完整提示词的必要选择

在执行封面生图或定稿新封面的完整提示词前，检查创作方式、画幅和人物是否已明确。未说明基础/创意时按 [creation-modes.md](creation-modes.md) 主动澄清；合并询问实际缺项，不把创作方式默认为基础。已有图提词不新增此问，直接沿用可判断的设置。下例以三项都未明确的生图请求为例，仅提示词时将提示语改为“写完整提示词前请选”：

```text
这期主要讲「从脚本到自动剪辑的完整流程」。
推荐封面标题：「AI 自动剪辑全流程」。

制作前请选：
1. 创作方式：当前基础风格（借鉴现有样图结构）/ 创意风格（重新构思构图和主视觉）。
2. 画幅：横屏 16:9 / 竖屏 3:4 / 横竖都要。
3. 人物：有人物 / 无人物。
```

三种输入都执行这项检查。这段是交互示例，实际摘要和标题来自当前输入。可以使用宿主的文本选择工具；没有该工具时直接提问并等用户回答。**等待时间不是用户的选择，不能因没有及时回复就自行生图。**

只缺一个项目时只问那个项目。用户已有“竖版、无人物”等明确表达时直接沿用，不要求再次确认；两项已明但创作方式未明时只问基础/创意。同一个封面的定点改字也沿用已经确定的选择。新视频只可采用明确授权免问的长期默认，按 [account-preferences.md](account-preferences.md) 核对授权；当前选择覆盖默认，缺一个仍问一个。

只有用户明确授权这两项都由 Agent 决定并且无需询问时，才可自行选择并说明采用值。普通「根据脚本帮我做」「按这个描述做」「直接做」不足以视为已回答两项。

「风格你决定」只授权创作方式/具体风格的选择，不自动授权画幅或人物；「画幅与人物你决定」也不自动回答基础/创意。用户明确授权三项都由 Agent 决定时，说明采用值后直接继续，不重复问卷。

有人物但未指定来源时，可默认原创虚拟人物或插画角色；参考图中的真人只提供构图与风格，不能自行沿用其身份。用户指定使用本人或其他照片时采用其指定素材；无人物时以内容对象承接主体。

## 汇成生图规格

用户完成必要选择后，将内容提炼、最终采用标题、所选参考特征、画幅与人物设置合并到一个规格。提示词应表达：

```text
输入类型：实际提供的脚本/视频描述/封面描述，可多个。
核心内容与依据：已有内容讲什么；纯画面描述无视频主题时留空，不虚构。
画面要求：用户明确指定的主体、场景、构图、配色、文字与禁止元素。
主视觉：具体画什么，以及它如何对应内容、画面要求和标题。
参考图：各图提供什么视觉特征或主体素材。
视频标题：用于内容理解与列表预览；记录是用户提供还是建议稿。
标题与封面配合：标题交代什么，封面文字与主视觉补充什么，共同承诺与内容依据；缺视频标题时记录未做联合检查。
封面文字（逐字）：最终主标题、副标题、必要标签与断行；保存文字清单。
画幅：用户选择及实际采用比例。
人物：有人物/无人物；有人物时的素材来源。
设计组合：构图、配色、质感、字形、情绪强度、文字密度。
构图与层级：按参考特征组织标题、主体与背景。
延展：所选基础分支或参考项；保留什么，变化什么，内容依据。
配色：背景、主标题、强调、辅助的角色；自主改色依据，网上来源（若使用）。
偏好依据：采用哪些长期设置，本次覆盖哪些项。
内容约束：不添加已有内容未支持的结果、数字或功能；无必要文字的道具保持无字，用户要求无字时全图不加文字。
```

需要实际生图时，随后按 [gpt-image-workflow.md](gpt-image-workflow.md) 选择通道并进入生图与验图流程；默认按 [prompt-export.md](prompt-export.md) 逐张补交完整提示词。仅提示词时直接按该提示词文档交付，不检测通道、不调用图片工具或 API，也不进行成图验收。验图同时检查内容对应关系、标题文字、标题与封面的共同表达、参考特征和用户选择，不只检查图片是否好看。旧封面诊断与改版先按 [cover-diagnosis.md](cover-diagnosis.md) 路由，已有图可判断的设置无需重新询问。
