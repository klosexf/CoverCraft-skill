# 旧封面诊断、修改优先级与改版提示词

用户要求诊断、点评或改进已有封面时读取。先看实际图，回答“问题在哪里、依据是什么、先改什么”，再按请求交付改版提示词或生成改版。诊断不会自动触发生图、风格菜单、API 配置或发布。

## 判断请求

| 请求 | 执行 |
| --- | --- |
| 诊断/点评这张封面、哪里有问题、怎么改 | `diagnosis_and_prompt`：诊断、优先修改项和完整改版提示词；不生图 |
| 只诊断、只给评审，或明确不要提示词 | `diagnosis_only`：只交付诊断与建议 |
| 反推这张图的提示词，近似复现 | `prompt_from_image`：按 [prompt-export.md](prompt-export.md) 还原可见规格，不主动点评或改版 |
| 诊断后重做、按建议生成一张 | 诊断后进入制作模式；当前指令已授权生图，不再追加一轮批准建议的步骤 |
| 只改这张图的某处 | 沿用主流程定点修改；不把局部修改扩成全面诊断或重设计 |

“怎么改”默认给建议与提示词；“帮我改图/重做/生成改版”明确要求实际修改时继续制作。用户只要诊断时，不为完成整套产物强加提示词。

## 先取得观察依据

- 查看用户指定的实际图片，记录来源、可读取的实际尺寸、可辨认文字、主视觉和人物模式。网页/截图含平台界面时区分封面区域与界面，后者不加入改版。
- 使用可用的只读查看工具检查完整图与约 320px 宽的小图，横竖按原比例显示；更小尺寸可辅助观察，不要求次要字都可读。不调用生图来制作诊断样图。
- 图片不可访问时先取得该图；不能依据占位符或描述编造分数。小图未实际查看时把该项标为 `not_checked`，不把原图缩小后的效果想象成观察。
- 诊断期间不要求补画幅、人物、视频标题、脚本或原模型。可见设置直接沿用；视频标题/内容已经提供时联合使用，没有时明确相应判断无法核验。
- 来源图中可辨认的文字记录为“观察到的原图文字”，不冒充用户已授权替换后的定稿。用户明确锁定或要求原样保留的文字不得自行缩短。

## 五项诊断

| 项目 | 实际看什么 | 常见优先修改 |
| --- | --- | --- |
| 信息清晰度 | 主题/问题能否理解，说明是否过多，同级信息是否竞争 | 建立一个核心表达，降低次要信息权重 |
| 主视觉焦点 | 视线先落在哪里，主体能否识别，文字和物件是否争抢 | 放大承担主题的对象，统一层级和阅读顺序 |
| 小图可读性 | 实际缩小后重要标题、轮廓、结果是否仍清楚 | 调整字号、断行、尺度和背景细节 |
| 明暗与颜色对比 | 文字及主体能否从各自背景分离，强调色是否抢错位置 | 调整背后明暗、减少竞争色或加必要分隔 |
| 真实性与可信度 | 可观察的失真、怪异结构、虚假 UI 外观；事实主张是否有给定内容依据 | 回看真实素材、去掉未经要求的宣称，标明待核验事实 |

每项输出 `score`、`status` 和 `evidence`：分数使用整数 0–5，5=清楚无明显问题，4=小问题，3=能用但有明显改进点，2=影响理解/阅读，1=严重问题，0=该项几乎失效。它是有观察依据的设计判断，不是 CTR 预测或平台表现评级，不计算“预计提升百分比”。

状态沿用 `pass` / `needs_fix` / `uncertain` / `not_checked`。没检查或无法判断时 `score: null` 并说明缺口，不能按零分处理。缺视频内容时不能把原图数字判为造假，也不能确认兑现；可给观察到的视觉可信度评分，事实核验另外记录 `uncertain`。真人身份/产品型号没有原始素材可比较时同样不声称已确认一致。

提供视频标题时按 [title-cover-alignment.md](title-cover-alignment.md) 加联合检查，独立于上述五项；没有标题仍完整诊断可见部分，不追加一个必答问题。

## 修改优先级

列出最多三项最值得先改的内容，每项包含“具体问题 → 修改动作 → 希望改善什么”。排序优先处理内容误导/文字错误、主题不清和小图不可读，再处理装饰或风格微调。问题不足三项时不要凑数；没有明显问题时明确说明，可以保留原图。

默认保留原图有效的主体、风格、画幅、人物和指定文字。确需全面重构时说明与具体问题的关系；用户只要局部改动时限于该范围。文案改写仅在用户授权时采用，否则放到建议中，不让改版提示词悄悄替换原文。

## 完整改版提示词

`diagnosis_and_prompt` 在已有信息足够时，按 [prompt-export.md](prompt-export.md) 写出修改后目标画面的完整自然语言正文：保留特征、修改后的布局/层级、人物与素材、比例、逐字文字和本轮限制都展开，不只写“放大标题，其余不变”。无须调用生图验证提示词。

默认继承旧图可判断且未被新要求覆盖的画幅和人物；无需套新封面问卷。重要文字看不清时先交付诊断、修改建议和缺项说明，记录 `prompt_status: needs_input`；取得原文后再定稿完整提示词，不猜字、不把占位符称成完整交付。比例/主体也无法确定且影响目标提示词时仅补必要缺项。若用户改变人物模式或比例，按新要求处理。

原图保留真实人物或产品时，列明需要附上的原图/原始素材及其角色，不仅用文字承诺保真。目标提示词依据为“旧图观察＋修改规格”，不是原图复现，也不是已生成的新图。生图后对应提示词再按最终画面整合。

## 进入实际改版

只有用户明确要求改图或生成改版时进入主流程通道、文字清单、生图与验收；延续上面的设置，不重新开风格菜单。使用旧封面作为修改目标，原始照片/截图作为辅助事实参考，并明确保留项。旧图无法作为当前工具的编辑输入时说明实际采取重生成路线，不能称为定点编辑。

修正次数沿用主流程上限。新图必须重新检查文字、人物、画幅、小图和适用的标题配合，旧图诊断分数不能作为新图验收通过；不在缺少发布数据时宣称点击率更高。

## 保存与交付

有可写工作区时，采用用户指定位置或 `outputs/video-cover-craft-<日期或主题>/`；没有写入能力直接在对话交付。

- `diagnosis.md`：一段主要问题、五项分数与观察依据、优先修改项、未核验项。诊断不会覆盖源图。
- `diagnosis.json`：`schema_version: 1`、`output_mode`、`source_image`、`observed_aspect`、`observed_people`、`observed_text`、`checks`（五项的 `score` / `status` / `evidence`）、可选 `title_cover_alignment`、`top_fixes`、`prompt_status`（`ready` / `needs_input` / `not_requested`）、`limitations`。
- 交付完整改版提示词时，再保存目标 `design-brief.md`、`text-spec.json`、`portable-prompt-<方案>-<画幅>.txt` 和 `prompts.json`；`source` 用 `redesign_spec`，`source_image` 指向诊断旧图，素材清单如实记录。
- 仅诊断或诊断＋提示词不新建 `generation.json`、新成图 `review.json`，不运行图片导出和主流程列表预览。可只读检查旧图的小图并记在诊断记录；明确旧图检查与新图验收的区别。
- 实际改版后另存生成/编辑记录及新图验收，同时保留诊断报告；按主流程交付真实图片与用户所要的提示词。
