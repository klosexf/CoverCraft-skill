# 生图通道：GPT Image 优先与平台回退

本文件仅用于需要实际生图的 `image_and_prompt` / `image_only` 模式。用户只要提示词或已有图提词时，转到 [prompt-export.md](prompt-export.md)，不执行通道检测、工具调用、API 配置与图片导出。默认成图交付后，同样按该文档补上完整的跨工具提示词；实际调用记录与可移植提示词分别保存。

## 默认选择顺序

先看当前会话已暴露的工具及其说明，按以下顺序选择：

1. **用户明确的通道选择**：本次指定优先于长期 `generation.backend` 偏好。明确选择 OpenAI API 时按 [openai-api-setup.md](openai-api-setup.md) 执行；明确限制“只用 GPT Image”时不回退到其他模型。
2. **GPT Image**：未指定通道时，优先宿主可调用、说明明确属于 GPT Image 的生图工具或已启用集成。不把聊天模型名称、平台名称或一个通用 `imagegen` 工具名当作型号证据。
3. **平台原生生图工具**：当前平台没有可用的 GPT Image 时，自动使用该平台自带且满足本轮必要输入要求的生图工具。此回退属于默认授权，简短说明“这里没有可用的 GPT Image，本轮使用平台自带的生图工具”即可，无须增加确认步骤。工具未披露型号时记录未知。
4. **没有可用生图工具**：说明缺少能力。用户可自行配置并选择 OpenAI 图片 API；未选择前不因发现 API Key 而调用 API。可交付设计和提示词，但不能称为已生成图片。

“没有可用 GPT Image”包括工具不存在、明确未开放或所需图像输入能力缺失。临时限流或网络错误先按宿主的错误处理要求处理，不把一次错误当作平台从来没有 GPT Image；确定无法继续时说明原因和可用回退。内容拒绝、权限拒绝或安全策略拒绝不通过换工具绕过。

选择原生工具时优先该平台声明的默认生图工具；多个候选时依据本轮参考输入、编辑、中文与画幅能力选择。不为默认回退自行接入另一家外部付费 API。

用户要求锁定具体型号时核对当前工具能否设置或证明该型号。无法保证时说明限制，不能用默认回退替代其明确指定的型号；用户可选择配置 OpenAI API。不得声称未知型号是最新 GPT Image。

| 当前条件 | 执行方式 |
| --- | --- |
| GPT Image 与平台其他生图工具都可用 | GPT Image |
| GPT Image 不可用，平台原生生图可用 | 平台原生生图，说明回退 |
| 上一行同时检测到 OpenAI API Key，但用户没有选择 API | 仍用平台原生，不自动使用 API Key |
| 用户明确选用已配置 OpenAI API，平台原生也可用 | OpenAI API |
| 用户要求只用 GPT Image，但 GPT Image 不可用 | 说明缺少通道，等待其选择 API 或解除限制 |
| 所有原生工具不可用，也没有已选定的可用 API | 交付设计草案，说明未生图 |

## GPT Image 内置通道：Codex 实例

在本 Skill 的目标 Codex 环境中，使用 `image_gen.imagegen`；经工具编排时对应 `tools.image_gen__imagegen`。工具名和能力以当前会话工具说明为准。通常也可读取宿主内置 `imagegen` Skill 获取运行要求；本技能的核心工作流不依赖它才能理解。

此 Codex 内置通道不需要用户配置 `OPENAI_API_KEY`。当前工具接口没有 `model`、`size`、`quality` 或 `output_path` 参数，不编造这些参数，也不把提示词中的尺寸要求当成原生尺寸控制。工具未返回确切模型 ID 时，报告「内置 GPT Image 通道，具体型号由宿主控制」。其他宿主的 GPT Image 参数以其工具说明为准，不能复制 Codex 的接口限制。

按主流程确定旧风格图是否作为图像条件；涉及创意策略或整体拒绝时才读 [creation-modes.md](creation-modes.md)。创意探索可省略未被用户要求使用的旧风格图，并用文字写清新视觉目标；必需身份、产品/界面素材或用户明确指定使用的参考仍须传入。记录实际角色与像素使用情况。

### 传入图像，而不是只写“参考图片”

1. **全部输入都有可访问的本地路径**：先查看每张图，再传 `referenced_image_paths`。数组顺序与提示词中的图片编号相同。
2. **至少一张目标图片只有当前会话附件**：使用 `num_last_images_to_include`，设为覆盖所需图片的最小最近图片数量，最多 5；它表示“最近 N 张图片”，不是任意选择图片 ID。注意新生成的图片也会占最近图片位置，下一次调用需重新核对。
3. 不同时传两个图像引用参数。混合来源时优先取得所有图片真实可读的本地路径；无法用一个机制覆盖必需图片时，请用户重新附上所需图片，而不是遗漏身份照片或关键参考。
4. 参考太多时可选择关键图，但先明确哪些图用于本轮。用户要求必须同时使用而工具无法容纳时，说明限制并索取适当输入。
5. 没有任何参考或主体素材时，两个引用参数都省略。

以下是本地图片示例，路径需换为实际已查看的文件：

```javascript
// @exec: {"yield_time_ms": 120000, "max_output_tokens": 500}
const result = await tools.image_gen__imagegen({
  prompt: "Use case: ads-marketing\nAsset type: 一张独立的16:9中文视频封面\nInput images: 图1仅为风格和构图参考，不沿用其人物和文字；图2为本期真实软件素材\nPrimary request: AI自动剪辑工作流；完全无人物\nStyle: 提取图1的真实视觉特征填在这里\nComposition: 根据图1调整到横版，标题与设备清楚分离\nText (verbatim): 主标题‘AI 自动剪辑’；副标题‘完整工作流’\nConstraints: 只生成一张完整封面，不做拼图；不生成任何人物，不沿用水印和平台UI；保留图2的可辨识布局",
  referenced_image_paths: ["/absolute/reference.png", "/absolute/software.png"],
  transparent_background: false
});
generatedImage(result);
```

仅有当前附件时，用 `num_last_images_to_include` 替换路径参数；其余字段不变。参考用于创作新封面时，在语义上属于“参考生图”，而不是直接修改原作者封面，即使该工具使用统一接口。

按工具说明给生成调用足够的等待时间。不要打印完整返回对象或 base64；用宿主媒体输出方法展示图片。返回值存在实际本地路径时，再复制到交付目录；没有文件路径时不要猜造路径或承诺已导出文件。

### 延展与配色写入提示词

提示词覆盖构图、配色、质感、字形、情绪与文字密度；组合确有需要时查 [design-dimensions.md](design-dimensions.md)。将 [text-and-preview-review.md](text-and-preview-review.md) 的本轮文字清单转成提示词：图中只写封面主/副标题与必要标签，视频标题留作内容和列表预览的元数据；无必要文字的背景道具无字。用户逐字要求优先，不因模板而缩写。

在 Style 与 Composition 中明确创作方式、用户锁定项、选取的继承特征、新构图/主视觉与内容依据；存在图像参考时再写其角色与范围。创意探索无须保持旧样图布局或字形。允许自主改色时，另写 Palette：背景、主标题、强调与辅助色分别用于哪里；说明不沿用原图色值，仍保留哪些结构特征。色值是生成目标，不保证精确匹配。

来自拼图的参考必须指定唯一目标格，例如「图1第一行第二张，R13-02 多臂工作助理；其他格不是本次参考」。指定格与本期人物模式一并约束，输出仍为一张独立封面。

### 修改本轮封面

本轮成图是第一修改目标，风格参考和人物照片是辅助输入。再次明确图片角色。例如：

```text
图1是待修改封面；图2只提供风格。
仅将图1副标题中的错字改为逐字正确的「完整工作流」。
保持图1的主标题、主体、构图、配色、人物模式和画幅。
输出一张完整修正后的封面，不并排展示修改前后。
```

若任务变为横竖版适配，明确它是重新构图，允许重新安排标题与主体；这时不要同时要求“所有位置完全不变”。

## 平台原生生图通道

沿用相同的输入分析、设计维度、人物选择和文字清单，将规格映射到当前工具实际支持的提示词、图像附件与画幅参数。Codex 的 `referenced_image_paths` 等参数仅用于上面的实例，不能直接传给其他工具。

- 参考图与照片必须真实传入；该工具不能接收必需参考时，说明限制，不能省略后声称已参照原图。用户允许仅按特征描述制作时才可放宽这一要求。
- 修改现有封面时核对是否支持输入目标图片或编辑。缺少能力时不把纯文字重画称为局部编辑。
- 比例、张数、文件返回方式均以当前工具为准；每个方案仍交付独立图片，横竖版分别构图。
- 按同一套文字、内容、人物、比例和小图标准验收，列表按交付深度执行；不因换平台取消核心检查。

记录 `execution_channel: platform_native`，实际工具名、已知供应方/型号，以及回退原因。供应方或型号不明确就写 `null`，不把聊天模型当成生图型号，不将平台原生成图标为 GPT Image。

## 可选：用户配置 OpenAI 图片 API

配置与执行见 [openai-api-setup.md](openai-api-setup.md)。普通“使用 GPT Image”表示生图偏好，不要求用户另配 Key。用户明确选择 API 或已授权持续使用 API 时才进入该路径；只设置 Key 和模型、不选择 API，不改变默认顺序。

在 Codex 可用时使用宿主维护的 `imagegen` CLI；其他支持本地脚本的宿主可使用本包的官方 SDK 助手 [openai_image.py](../scripts/openai_image.py)。不会自动购买额度、写入真实 Key 或把 Key 打包。

## 画幅与交付目标

| 画幅 | 常用交付尺寸 |
| --- | --- |
| 16:9 横版 | 1920 × 1080 |
| 4:3 横版 | 1440 × 1080 |
| 3:4 竖版 | 1080 × 1440 |
| 9:16 竖屏 | 1080 × 1920 |
| 2:3 竖版 | 1080 × 1620 |
| 1:1 方形 | 1080 × 1080 |

接受用户自定义比例和尺寸。以上是导出目标，不保证当前工具支持原生尺寸参数；按真实接口设置或写入提示词，再读取实际图片尺寸。比例错误先用生图工具重新构图或扩展画布，缺少能力时说明；只有比例相符才等比缩放。横竖版分别安排标题与主体，不机械裁切或拉伸。

## 保存实际生成记录

使用用户指定位置；未指定则放当前工作区 `outputs/video-cover-craft-<日期或主题>/`。真实返回路径可复制/保存，没有路径时用宿主原生媒体交付，不猜造文件。没有文件写入能力时在对话交付已有产物与记录并说明未保存。

- `design-brief.md`：简短记录实际输入、内容依据、用户画面要求、封面文字来源、画幅/人物/数量、参考角色和像素使用情况。标记 `output_mode`、`input_modes`、`delivery_depth`、`creation_mode`、适用的 `creative_strategy`、锁定/继承/重新设计与本轮拒绝项；配色角色、偏好覆盖和视频标题按实际情况补充，无依据的字段可留空。只写与本轮决策有关的内容，不为填字段制造问题。
- `text-spec.json`：本轮允许的逐字文字与断行，结构见 [文字与预览验收](text-and-preview-review.md)。
- `prompt-<方案>-<画幅>.txt` 与 `generation.json`：仅记录真实生成/编辑调用，包括通道、工具、已知供应方/型号、请求型号、回退原因、实际图像输入与图片尺寸、必要的导出尺寸。未知型号为 `null`；API 请求型号与实际返回型号分开，不把聊天模型当生图型号。
- `review.json`：仅为实际成图记录核心检查、适用的列表检查、可见依据与修正历史，格式见验收文档。
- 完整可移植提示词与素材依赖按 [prompt-export.md](prompt-export.md) 保存，与原始调用记录分开；仅图片任务不要求额外写可移植提示词。

快速交付同样保留简短设计依据与真实检查记录；不以减少预览文件为由省略文字清单或冒称验图通过。只有实际完成导出/预览时才列相应文件。

## 按深度导出已经生成的图片

**快速交付默认保留原图与用户点名的格式/尺寸，完成完整图和约 320px 小图检查，不默认运行下面的整套导出或列表助手。** 小图可用宿主的缩略显示或单张等比缩略文件检查。只指定一种格式/尺寸时仅补该产物；不得以格式转换修复内容或中文。

完整预览使用本技能的导出脚本，例如：


```bash
python3 /absolute/video-cover-craft/scripts/export_covers.py \
  --image /absolute/generated-a.png \
  --image /absolute/generated-b.png \
  --out-dir /absolute/outputs/cover-final
```

可为相同比例的图片添加 `--size 1920x1080`。不同画幅分开执行。脚本拒绝明显比例不符的图片，不裁切、不拉伸画面；只做等比尺寸调整、格式转换与对比预览。

保留生成原图；导出图和缩略图是派生文件。中文标题错误不能靠这个脚本修复，必须回到图片工具。导出后查看 `index.html` 和实际 PNG/JPEG，检查结果才是交付依据。

完整预览或用户点名列表时，再运行 [preview_feed.py](../scripts/preview_feed.py)，用真实图片和已有视频标题生成列表预览，操作见 [text-and-preview-review.md](text-and-preview-review.md)。没有视频标题不强制补写。预览只复制输入图片并叠加页面元素，不修改图片字词、内容或尺寸。实际打开后将检查依据写进 `review.json`；打不开或缺依赖时标明未检查并交付已有文件，不宣称完整检查已通过。

用户回传完整预览的批注或修改单时，按 [批注与版本复核](preview-feedback.md) 匹配原图、保留锁定项并在已授权范围内改图；新旧图一同生成预览，用 `--current-image` 指定本轮新图、`--previous-image` 指定本轮修改目标原图，必要时用 `--feedback` 带入历史批注；当前新图默认进入批注页。页面资源和图片副本随 HTML 一起交付。
