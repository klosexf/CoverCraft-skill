# Video CoverCraft 2.13.0 · 视频封面工坊（制作、提示词与旧图诊断）

根据**视频脚本、视频描述或封面描述**生成封面与可供其他生图 AI 使用的提示词，任一种输入都可以，也可组合；支持横版、竖版和可选人物。图片主流程是：**理解需求 → 补齐创作方式、画幅与人物 → 设计并生成 → 核心验图与修改 → 按深度交付图片和提示词**。也可跳过生图，只完成提示词。

你可以提供完整脚本，也可以只说明视频讲什么，或者直接描述想要的主体、场景、构图、文字和配色。描述已足够时，不要求补交完整脚本。标题和参考图都是可选的：明确指定的标题逐字采用，未提供时根据已有内容拟写；要求无字封面时不加文字。

制作新封面或其完整提示词前会核对**基础/创意、画幅和人物**，尚缺的选择合并问一次，已经说清的不重复问。也可明确授权 Agent 决定；「风格你决定」只授权风格，画幅与人物未明时仍会补问。选择有人物并不要求本人出镜，可用指定照片或原创角色。已有图提词、诊断与局部改版沿用可判断的设置，不追加创作方式问卷。

## 快速交付与完整预览

主流程按任务加载细则，普通制作默认快速交付；需要完整文件或列表比较时再增加预览，不多问一道深度选择题。

| 深度 | 适合怎么用 | 交付与检查 |
| --- | --- | --- |
| **快速交付（默认）** | 「做一张封面」或「快速交付」 | 原图或指定格式、完整提示词（仅图片时省略）、简短检查说明；查看原图和约 320px 小图，核对中文、主体、人物、画幅和边缘 |
| **完整预览** | 「完整预览」「给列表预览」或「做缩略图对比」 | 保留核心验图，增加 PNG/JPEG、缩略图对比页、浅/深列表、320/168/120px、模拟遮挡与裁切检查 |

可以在下方任一制作示例末尾加「快速交付即可」或「请完整预览，给格式导出与列表对比」。只要一种格式或一个附件时按要求补足。两种深度都支持常规或创意风格；「只要提示词」仍只交付文字，不因完整预览自动生图。未实际查看的项目会如实标明。

[核心验收与预览细则](references/text-and-preview-review.md) · [图片交付与导出](references/gpt-image-workflow.md)

## 图片和提示词都能交付

普通“做封面”默认附上每张图对应的完整提示词，可以复制给其他生图 AI；封面经过修改后，提示词会整合最终画面，不只保留最后一条修改指令。明确说“只要图片”时不额外展示提示词。

说“只要提示词，不生图”时，完成相同的设计分析，直接交付文字，不调用图片工具或 API，也不要求先配置生图能力。没有指定其他 AI 的名字时给通用自然语言版本，不强制追问平台。也支持查看你提供的已有封面，写出基于可见特征的近似复现提示词，无法反推出作者真实的原始提示词或种子。

提示词写清主体、构图、配色、质感、光线、画幅、人物和逐字标题，不依赖本机路径或技能编号；有必须另附的人物照片、真实软件截图时列出素材与角色。跨模型的排版、中文准确性和细节可能不同，不保证完全复刻。细则见 [跨工具提示词交付](references/prompt-export.md)。

```text
$video-cover-craft
只要提示词，不生图，给其他生图 AI 使用。
封面描述：竖版 3:4，无人物；奶油白与薄荷青纸雕风，文档漂浮在左侧，右下方是笔记本。
主标题逐字写「先聊清楚，再开发」，上方大字；一套，不需要参考图。
```

## 标题与封面一起检查

设计时记录“视频标题交代什么、封面文字与画面补充什么、共同承诺什么”；提示词把它落实为具体主视觉，生成后再把标题和实际图片一起检查。品牌和主题词可以合理重复，指定文案保持原文；没有视频标题时只检查封面自身，不要求额外补标题。细则见 [联合检查](references/title-cover-alignment.md)。

## 诊断已有封面与改版

说“诊断这张封面，看看哪里有问题”，会查看原图和可执行的小图，按信息清晰度、主焦点、小图可读性、明暗/颜色对比、真实性五项给出设计分数与依据，再列最多三项优先修改和完整改版提示词。默认不生图；明确“只诊断，不要提示词”时只给评审，明确“诊断后重做”时继续生成改版。

诊断不额外要求脚本、视频标题或风格选择，可见画幅与人物直接沿用。看不清的关键字不猜写，先交诊断并指出提示词待补；没有内容依据时不能判断原图数字是否真实，设计评分也不预测点击率。改版保留指定文案和原图有效特征。细则见 [旧封面诊断](references/cover-diagnosis.md)。

```text
$video-cover-craft
诊断我附上的这张封面，给分数、优先修改建议和完整改版提示词，不生图。
保持原图画幅、人物模式和标题原文。
```

仅要求“反推这张图的提示词”时仍提供近似复现，不自动改版；只改某处时沿用定点修改流程。

## 常规风格与创意风格

当前基础风格（也称常规风格）借鉴 AI 博主的主题表达与信息层级，字体、颜色和材质可变化；创意风格包含从结构延展和从内容探索，重新设计构图、字形、质感与主体比喻。两种都支持生图或只交付提示词。未说明创作方式时会主动询问并等待回答，不直接默认为基础：

```text
这次按当前基础风格（常规）生成，还是用创意风格重新设计？
基础风格：借鉴现有样图的表达结构，按本期内容调整。
创意风格：重新构思构图和主视觉，字体、配色、材质也可重新设计。
```

已选基础/创意、选定内置风格、授权「风格你决定」或沿用同一封面的选择时不重复问。单给参考图、配色或材质还需澄清；选择创意不会推翻已锁定的画面要求。局部修改、已有图提词、只诊断、浏览或拟标题不加此问；创意延展/探索由 Agent 判断，不再问子模式。

可以直接说「用创意风格，跳出原样图的字体和颜色，横版、无人物，只要提示词」。说「这些风格全部不喜欢」会退出当前推荐，沿用既定内容、文案、画幅、人物与必要素材，探索新方向；局部不满意只改对应维度。只要一张就做一套，不自动生成三张。

验收按本轮设计目标和用户明确保留项进行，创意方案不因允许改变的外观偏离旧图而判失败；中文、主题、小图可读性、人物与画幅仍检查。参考素材不自动成为锁定要求。详见 [创作方式与反馈处理](references/creation-modes.md)。

## 先看图选风格

[十种真实样图菜单](references/style-menu.md) · [离线可选图库](style-picker.html)。不知道风格时，先按内容推荐最多三种并展示图片，或直接浏览全部十种。回复编号即可，例如 `B02，竖版，无人物`；也可说 `风格你决定`。样图中的人物、题目、配色和画幅均可更换。

明确说先看再选，会等待选择后生成；可在展示样图的同一轮澄清基础/创意，选 B 样图就采用基础。已定具体风格或参考不重复开菜单，但参考图本身不代替创作方式选择。仅浏览风格不要求脚本、画幅、人物或创作方式。图片不能内联显示的平台提供真实文件链接或 GitHub 图文菜单，不保证所有平台都有相同的图片交互界面。

## 三种输入方式

| 你提供什么 | Skill 怎么处理 |
| --- | --- |
| 视频脚本 | 提炼核心内容、方法与关键关系，确定标题和主视觉 |
| 视频描述 | 根据选题或内容简介生成，不要求完整脚本 |
| 封面描述 | 直接落实主体、场景、构图、文字、配色和风格要求，可以没有视频内容 |

多种输入一起提供时，结合内容事实和你的画面要求；没有指定的细节可以自主延展。纯画面描述不会被扩写成虚构的视频内容，视频标题允许留空。只有描述太空泛、缺少核心主题或画面意图，或输入存在实质矛盾时，才补问关键问题。处理细则见 [输入与标题处理](references/script-to-cover.md)。

默认优先 GPT Image；当前平台没有可用的 GPT Image 时，使用该平台自带的生图工具。选定工具生成整张封面和中文标题；HTML 用于查看结果。参考图提供视觉方向，场景、构图与配色可以根据本期内容延展。

## 跨平台生图顺序

1. 当前平台有可调用的 GPT Image，优先使用。
2. 没有可用的 GPT Image，自动调用平台自带的生图工具，说明实际通道。
3. 用户可以自行配置并明确选择 OpenAI 图片 API；该选择优先于默认顺序，仅存在 Key 不会自动启用 API。

平台没有任何可用生图工具、也没有选定的可用 API 时，会说明缺少能力并提供设计草案。Skill 不会替平台凭空增加工具；能读取 Skill、查看并传入参考图、调用生图工具的 Agent 才能执行完整流程。聊天模型与生图模型分别识别，未知型号不会猜成 GPT Image。

API 路径、环境变量、依赖与运行示例见 [OpenAI API 配置说明](references/openai-api-setup.md)。其他支持本地脚本的宿主可使用包内的官方 SDK 助手；Codex 优先使用其维护的 API 客户端。用户指定“只用 GPT Image，不要回退”时遵从该限制。

## 其他已支持的能力

1. **视频标题与封面联合检查**：分别记录视频标题、封面文字与主视觉，检查共同表达与内容依据；明确给出的封面文字逐字保留，只提供未区分用途的“标题”时仍作为封面标题，不自动缩写。
2. **风格自由组合**：构图、配色、质感、字形、情绪强度、文字密度分别选择，可把基础结构延展成纸雕、摄影、漫画等一致的组合。扩展为十种 AI 基础风格、30 个分支，保留 31 个原参考项。
3. **账号偏好与系列模板**：记住你明确要求长期沿用的规则，当次要求优先。默认配置允许自主选择配色，画幅和人物未预设；只有明确的长期要求才会保存。
4. **列表预览**：浅/深色背景、320/168/120px 小图、模拟时长和点赞遮挡、边缘裁切及周边示例卡片。预览不修改图片；模拟界面不是平台规范。
5. **中文专项验收**：逐项核对主副标题、品牌、流程标签、数字及背景杂字，记录未核验和需要修正的项目。依赖实际看图，不保证首图零错字。
6. **旧封面诊断与改版**：依据可见图片给五项设计分数、修改顺序与目标提示词；用户要求改图时再进入生成与验收。

细则见 [标题处理](references/script-to-cover.md)、[设计维度](references/design-dimensions.md)、[账号偏好](references/account-preferences.md) 和 [文字与预览验收](references/text-and-preview-review.md)。
## 使用条件

- 支持提供所需工具的 Agent 宿主；Codex 的内置 GPT Image 通道不需要另配 API Key。
- 内置通道的具体模型版本由宿主控制，技能不能通过不存在的参数锁定型号。
- 可选 API 使用用户指定的 GPT Image 型号和支持参数，不硬编码最新型号。参考 [OpenAI 图片 API 指南](https://developers.openai.com/api/docs/guides/image-generation)。
- 平台原生工具的参数、参考输入、编辑与尺寸能力以实际工具说明为准，不能照搬 Codex 参数；生图能力缺失时如实说明。
- 导出助手可选，需要 Python 3.9+ 和 Pillow；生图本身不依赖导出助手。
- 列表预览助手同样使用 Python 3.9+ 和 Pillow；页面本身可离线查看，无需额外服务。

## 安装

解压包，进入 `video-cover-craft` 文件夹，运行：

```bash
python3 scripts/install_skill.py --target codex
```

默认安装到 `${CODEX_HOME:-~/.codex}/skills/video-cover-craft/`。也可用 `--destination /absolute/skill-root` 指定技能目录，例如 `~/.agents/skills`。一次只安装到一个技能根目录，避免同名版本重复。

其他平台请按其 Skill 导入方式放入完整的 `video-cover-craft` 文件夹；`SKILL.md` 是入口，参考文档、原图和脚本一并保留，不只复制一个提示词文件。这个安装助手默认目标是 Codex，不假定其他平台采用相同发现目录。

已有同名技能时，默认拒绝覆盖。确需替换可用 `--replace`，原目录会先保留在技能根目录旁边的 `skill-backups/video-cover-craft/` 中，避免备份被误发现为另一个 Skill。安装后重新加载会话；安装不会为旧会话凭空增加缺失的图片工具。

替换安装时保留原有 `user-preferences.json`，不会用新版默认配置覆盖个人设置。以后可直接说“记住，这个系列沿用大标题和设备场景，配色你决定”；一次性的“这张选 A”只影响本期。

旧名升级：如果此前安装为 `cover-craft` 或 `cover-studio`，先把旧技能文件夹改名为 `video-cover-craft`，再运行本版安装助手并加 `--replace`；安装助手会备份旧版并保留 `user-preferences.json`。同一技能只保留一个安装入口。

## 使用方式

在已安装技能的 Agent 中，输入 `$video-cover-craft`，再描述任务；需要参考图、人物照片或旧封面时一起附上。视频脚本、视频描述、封面描述任选一种即可。新制作时写清**画幅、有人物或无人物、数量**，未想好的标题和风格可以交给 Agent；也可以明确说「画幅与人物都由你决定，无需再问」。

没说基础还是创意时，Agent 会先问，不直接套常规风格。说「风格你决定」可授权自主选择，但不自动授权画幅与人物；这两项已写清就不再问。

不使用 Skill 的其他生图 AI，可以直接使用本技能交付的完整提示词。普通风格描述不需要安装图库；需要保留真实人物身份或准确界面时，按素材清单另附原图。

| 想拿到什么 | 怎么说 | 是否生图 |
| --- | --- | --- |
| 图片与完整提示词 | 「做一张封面」 | 是，默认两者一起交付 |
| 只有图片 | 「只要图片，不附提示词」 | 是 |
| 只有设计提示词 | 「只要提示词，不生图」 | 否 |
| 已有图的近似复现提示词 | 「反推这张图的提示词」并附图 | 否 |
| 旧图评审与改版提示词 | 「诊断这张封面」并附图 | 否 |
| 只有旧图评审 | 「只诊断，不要提示词，不改图」 | 否 |
| 诊断后生成改版 | 「先诊断，再重做一张」 | 是 |

### 1. 给视频描述，快速制作

没有完整脚本也能用。下面已指定画幅、人物与数量，可以直接设计和生成：

```text
$video-cover-craft
视频描述：先在 ChatGPT 讨论需求，整理开发说明，再交给 Codex 实现。
竖版 3:4，无人物，只做一张。
封面标题请帮我拟写，常规风格和配色你决定。
生成图片，并附上对应的完整提示词。
```

### 2. 给完整脚本，提炼主视觉

可粘贴脚本，也可附上可读取的脚本文件；无需先自行整理摘要。

```text
$video-cover-craft
请根据下面的脚本做一张横版 16:9、无人物封面。
封面主标题逐字写「从脚本到成片」，常规风格你决定。
脚本：今天演示用 AI 辅助剪辑口播视频。
先导入素材并转写，再删掉停顿与重复句，最后人工检查字幕并导出。
```

### 3. 直接描述画面，不提供视频内容

已想好画面时可以直接落实。需要无字封面就明确写「全图无文字」。

```text
$video-cover-craft
封面描述：竖版 3:4，无人物，奶油白与薄荷青的纸雕画面。
左侧漂浮文档，右下方放一台笔记本，中间用柔和光线连接。
上方主标题逐字写「先聊清楚，再开发」。
生成一张图片，不需要我补视频脚本。
```

### 4. 先看真实样图，再选风格

```text
$video-cover-craft
视频描述：教大家把重复的资料整理工作交给 AI。
先给我看三种适合的真实样图，我选完你再生成。
竖版 3:4，无人物，一张。
```

看过后回复 `B02，按这个风格做` 或 `你帮我决定`。只想浏览时，可以说 `$video-cover-craft 我只想看看全部风格，先不要生成`。离线图库也能点击卡片、复制选择句，再发回聊天。

### 5. 用创意风格，延展结构或探索新方向

```text
$video-cover-craft
视频描述：把会议记录整理成任务与负责人清单。
封面主标题逐字写「开完会，谁来做？」。
用创意风格，从内容重新构思主体比喻和构图，不套旧样图。
重新设计字体、配色和材质；横版 16:9，无人物，只做一张。
生成图片和完整提示词。
```

想从已有结构延展，可把创意要求改为「保留 B07 的左右对比关系，用纸质拼贴重新设计对象、字体和配色」。常规、创意都可以搭配「只要提示词，不生图」。

### 6. 只写提示词，交给其他生图 AI

```text
$video-cover-craft
只要能复制给其他生图 AI 的完整提示词，不生图。
视频描述：先整理开发需求，再开始写代码。
封面主标题逐字写「先聊清楚，再开发」。
横版 16:9，无人物，一套；风格和配色你决定。
提示词请完整描述画面，不依赖技能编号或本机文件路径。
```

这种用法不需要配置生图工具或 API Key。未指定目标 AI 时直接给通用版本；需要英文画面描述时可追加「提示词用英文，图中中文标题保持原文」。

### 7. 从已有封面提取提示词

附上要分析的图片，适合想在其他工具里制作近似画面的情况。

```text
$video-cover-craft
请根据附图写出近似复现的完整提示词，不重新生图。
沿用可见的画幅、人物、构图、配色、质感和标题。
标题原文是「先聊清楚，再开发」。
```

得到的是基于画面观察的描述，无法找回作者真正的原始提示词或种子。仅提词不会自动改版。

### 8. 诊断旧图，或诊断后直接重做

只想知道怎么改，并拿到改版提示词：

```text
$video-cover-craft
诊断附上的旧封面，给设计分数、观察依据、优先修改建议和完整改版提示词。
保持原图画幅、人物模式及标题原文，不生图。
```

只要评审，在上面的指令里追加「不要提示词」。想实际生成改版，可以改用：

```text
$video-cover-craft
先诊断附图，再按最值得改的地方重做一张。
保留原图画幅、人物模式及标题原文，改善文字层级和背景干扰。
交付新版图片与完整提示词。
```

图中看不清的关键文字需补充原文；设计分数用于解释画面问题，不预测点击率。

### 9. 多张素材分工：风格、人物、软件界面

同时附上对应图片，说明每张的用途；选择有人物也可以使用原创虚拟角色。

```text
$video-cover-craft
第1张是风格参考，只借鉴构图和标题层级。
第2张是本期要使用的人物照片，第3张是要保留的软件截图。
主题：AI 辅助剪辑工作流；封面主标题逐字写「自动剪辑全流程」。
横版 16:9，有人物，一张；使用第2张人物，不沿用第1张中的脸。
生成图片和提示词，并列出复制到其他生图 AI 时必须另附的素材。
```

### 10. 同一主题做横竖版，或多个独立方案

```text
$video-cover-craft
视频描述：用 AI 整理零散资料，建立可检索的知识库。
封面主标题逐字写「资料终于找得到」，无人物，常规风格你决定。
横版 16:9 和竖版 3:4 各一张，共两张。
分别安排构图，每张都附上对应的完整提示词。
```

想比较不同构思，可将数量要求改成「横版 16:9，做两个不同构思，每个单独出图，共两张」。横竖版分别设计；只有一张时不会自动扩成多方案。

### 11. 后续修改：局部调整或整体换方向

在已有成图的同一对话中，可以直接追加：

```text
只放大主标题，其他文案、设备、背景、配色和画幅保持不变。
请编辑这张图，并同步更新完整提示词。
```

如果当前推荐的风格都不喜欢：

```text
这些风格全部不喜欢，不要科技蓝、发光设备或任务卡。
沿用已确定的标题、画幅和人物设置，从内容探索一个新方向。
这次只要一套完整提示词，不生图。
```

局部反馈只改对应范围；整体否定会退出当前菜单。仍想用常规方式时，追加「这次仍要常规风格，不做创意探索」。

### 12. 保存系列偏好，减少重复说明

```text
$video-cover-craft
记住：我的「AI 实用教程」系列默认竖版 3:4、无人物，这两项以后不用再问。
保持大标题和设备场景，配色你决定。
本期有明确要求时，以本期要求为准。
```

只有明确要求长期记住才保存；「这张选 B02」等单次选择只影响当前任务。

需要选用自行配置的 OpenAI 图片 API，见 [API 配置与调用](references/openai-api-setup.md)；仅配置 Key 不会自动改成 API 生图。

## 基础风格与延展

共 **10 种 AI 基础风格**：黄蓝冲击、蓝黑科技、白橙清单、彩色漫画、极简编辑、发布会实测、双阵营对比、未来办公、矩阵控制室、立体概念。每种有三个构图/场景分支，共 **30 个**。默认案例围绕 AI，不主动拓展到美食、旅行、手作、空间改造或电影选题。见 [基础风格目录](references/style-catalog.md)。20 位创作者的观察已逐项进入全部 30 个分支，每条注明来源、变化方法、人物/画幅适配与验收重点。新增 10 张实图，每类验证一个分支；另 20 个尚未逐个生图。

[查看 10 类新实图与验图](references/style-validation.md)。PNG、320px 小图、实际提示词和记录均在 `assets/style-examples/`，导入其他平台时一并保留，可作为真实像素参考。

网上调研已扩展为 **20 个 AI 创作者账号、41 张实际查看的封面**：YouTube 14 位，哔哩哔哩 6 位。每位都有具体视频来源、可见特征与适用于本 Skill 的延展建议，见 [逐位调研报告](references/ai-creator-cover-research.md) 与 [完整来源清单](references/ai-creator-cover-sources.json)。制作时按 [内容结构与配色用法](references/ai-cover-patterns.md) 匹配本期主题，包含六组自主延展配色，以及人物版转无人物版的规则。网上样本另计，不改变内置原参考、基础风格或已生成案例的数量。

[原参考档案](references/user-reference-library.md) 的 17 项和 [新增横版档案](references/horizontal-reference-library.md) 的 14 项分别有两种延展建议。新增项包括深色发布会实测、冷暖双阵营对比、勾叉观点辨析、产品实测问答、太空夸张体验、多臂工作助理、魔法入门教程、航海全解教程、矩阵控制室、云端理想世界、未来悬浮办公、国风专家模式、白底产品聚焦、微缩岛屿世界；都有无人物与竖版适配方法。

这些数量含义不同：10 是基础风格，30 是基础分支，31 是原参考项；它们可能相近，不相加成风格总数。未指定具体分支时会按本期内容与画面要求选择，默认适度延展；只要一张时只做一张。

## 配色可以自主变化

基础名称和原图颜色都是起点，可以根据已有内容、画面要求、主视觉和可读性改色，借鉴网上搭配后再调整。用户明确指定品牌色或某组颜色时才锁定，无需增加额外的必答配色问题。

已加入午夜橙蓝、电光紫青、柠檬紫墨、晨雾薄荷、深绿暖金、靛蓝蜜桃、奶油莓果、海盐糖果八组起点，另可继续创作。后三组保留公开色卡的作者与来源；见 [配色方法与来源](references/color-palettes.md) 和 [配色色卡预览](palette-preview.html)。色卡不是生图样张，最终可读性仍检查实际成图。

$video-cover-craft
参考 R12-02 冷暖双阵营对比，延展成两工具接力。
请根据我提供的视频脚本做一张竖版 3:4，无人物。
没有标题，请帮我拟写；配色你决定，可借鉴网上好看的搭配。

## 输出与限制

默认快速交付真实原图或指定格式、完整提示词与简短检查说明，不默认生成格式导出与列表页面。完整预览再增加 PNG/JPEG、缩略图对比页与列表检查；两种都保留完整图和约 320px 小图的中文、内容、人物、画幅和边缘核对。设计摘要、文字清单、实际调用和检查记录按本轮事实保存，细则见 [图片交付](references/gpt-image-workflow.md)。

跨工具版本单独保存为 `portable-prompt-<方案>-<画幅>.txt`，并用 `prompts.json` 记录对应图片与素材依赖；横竖版分别安排构图。只有比例相符时进行等比尺寸调整，不会把一张拼图冒充多个独立方案。

仅提示词时交付文字正文、提示词文件、设计摘要与文字清单；不交付虚构图片、生图记录或验图通过结果。已有图提词同样不会自动重新生成图片。

旧图诊断交付 `diagnosis.md` / `diagnosis.json`；附完整改版提示词时同时保存目标设计、文字清单和提示词映射。旧图分数不作为新图验收，也不承诺发布表现。实际重做后另存真实生成记录与新图检查结果。

AI 成图默认是扁平图片，不附带自动分层源文件；要求独立可编辑文字时可选择额外排版。中文标题与身份仍需生成后检查，不能保证每次首图就正确。

内置参考库提供可复用的视觉档案与原图；封面主体、文案和场景根据当前制作要求重新设计。
